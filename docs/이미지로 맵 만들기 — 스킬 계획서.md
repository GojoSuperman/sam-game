# 이미지로 SPUM 맵 만들기 — 스킬 계획서

작성 2026-08-20. **여기 적힌 숫자는 전부 실측**이다 — 실제로 이미지를 돌려보고 나온 값이며,
실패한 시도와 그 원인까지 남겼다. 내일 검토 후 스킬로 굳히는 것이 목표.

## 1. 무엇을 만드는가

사용자가 **"이런 맵 만들어줘"** 라고 하면:

```
① 나: 이미지 생성 프롬프트를 준다 (판독 가능한 규격으로)
② 사용자: AI 로 이미지 생성 → 다운로드 폴더에 저장 → "생성했어"
③ 나: 판독 → 검증 → 자동 개통 → 미리보기 + Studio 주입 스니펫
④ 사용자: 미리보기 확인 → 콘솔에 스니펫 붙여넣기
```

자연어만으로 레이아웃을 짜면 격자적이고 단조롭다. AI 는 **배치를 상상하는 일**을 하고,
정확한 변환·검증은 코드가 한다. 그게 이 분업의 이유다.

## 2. 핵심 설계 — 짝 이미지 (그림 + 마스크)

한 캔버스에 **위=예쁜 그림, 아래=색 코드 마스크**를 받는다.

| | 역할 |
|---|---|
| 위 판 | 그대로 **맵 그림**이 된다 (격자로 잘라 같은 위치에 되놓으면 원본과 동일하게 보인다) |
| 아래 판 | **통행 판정**만 읽는다 (벽·가구·식재·물·야외) |

### 왜 두 판인가 — 실측 근거

그림 한 장에서 색으로 판정하는 것은 화풍에 따라 **실패한다**:

| 이미지 | 결과 |
|---|---|
| 실제 건축 도면 (세피아 렌더) | 초록 픽셀 **0.1%** (96/66,010). 벽·바닥·포장이 모두 색조 h30 에 명도만 달라 가구와 벽이 구분 안 됨 |
| 색 코드 마스크 | 판독 **저신뢰 0칸** (순수 채도색이라 JPEG 잡음에도 견딤) |

두 번 생성하면 배치가 어긋난다. **한 캔버스에 두 판**이면 어긋날 위험이 훨씬 작고,
어긋난 정도를 코드가 측정할 수 있다 (정렬 일치도).

## 3. 확정된 프롬프트

**2026-08-20 villa7 에서 정렬 91% · 자동 개통 후 도달 97% 를 낸 것.**

```
Produce ONE image containing TWO stacked panels showing the SAME single level.
Separate the two panels with a pure white horizontal band about 20 pixels tall.
Both panels must be the same width and the same height in pixels.

CRITICAL — count these exactly, do NOT duplicate or tile the level:
  - ONE building only, centered, surrounded by forest
  - ONE courtyard at the horizontal center of the building
  - TWO kitchens total (far left, far right)
  - TWO living rooms total (top center, side by side)
  - TWO TV rooms, TWO offices, TWO guest baths (one of each per side)
  - ONE fountain at the center of the ONE courtyard
  - ONE thick continuous outer wall wrapping the entire building
  - ONE stone path leading from the building's south entrance into the forest

VIEW — both panels use the SAME 2.5D quarter view:
top-down game map in three-quarter perspective, like a 16-bit SNES era RPG
interior. Walls are drawn with a visible top surface AND a visible front face so
you can see the wall thickness. Furniture is drawn from a slightly tilted angle
so its front is visible. Everything aligned to a square tile grid.

TOP PANEL — the finished game art (this is the actual game map):
16-bit pixel art Mediterranean villa surrounded by forest. Warm limited palette:
cream travertine floor tiles, terracotta clay tiles, dark walnut plank floors,
pale stucco wall faces with dark wood trim. A thick dark stone outer wall wraps
the whole building so its outline reads clearly. Outside the wall: dense forest —
pine and broadleaf trees, grass, shrubs, a stone path to the south entrance.
Furniture: kitchen counters with sinks and stoves, sofas, armchairs, dining
tables with chairs, bookshelves, patterned rugs, beds, bathtubs and toilets.
Real windows set into the wall faces with visible frames and glass. Real wooden
doors with visible panels and handles, EVERY door standing fully open with a
clear walkable opening. Courtyard with potted fan palms, clipped hedges, and a
tiled fountain with blue water. Hard pixel edges, no anti-aliasing, flat even
lighting, no cast shadows.

  TOP PANEL PALETTE RULE — critical:
  the top panel is finished game art. It must contain NO pure saturated colors
  anywhere — no pure yellow, no magenta, no pure green, no pure cyan, no pure
  blue. Only warm muted natural tones. The pure colors belong ONLY to the
  bottom panel.

BOTTOM PANEL — a FLATTENED color-coded overlay of the EXACT same view, same
scale, same position, pixel aligned to the top panel. Do NOT copy the artwork:
replace every element with ONE solid block of its category color. Use ONLY
these six colors and nothing else:
  #000000 = walls, including wall top surfaces, wall front faces, and windows
  #FFFFFF = walkable indoor floor, including door openings and rugs
  #808080 = walkable outdoor ground: forest floor, grass, stone path, courtyard
  #FF00FF = furniture and fixtures
  #00FF00 = trees, shrubs, hedges, potted plants
  #0000FF = water

Bottom panel rules — these matter most:
  - use ONLY those six colors, each fully saturated and exact
  - FLATTEN everything: a tree becomes a solid #00FF00 rectangle, never a drawn tree
  - rugs, carpets and mats are ALWAYS #FFFFFF (walkable), NEVER #FF00FF
  - door openings are #FFFFFF because you can walk through them
  - windows are part of the wall: paint them #000000
  - no outlines anywhere — each element is ONE solid block of its color
  - walls at least 2 tiles thick so they read clearly

Hard rules:
  - a BLANK UNLABELED map: absolutely no words, letters, numbers, titles,
    legends or watermarks anywhere in either panel
  - FIRST floor: no stairs anywhere
  - both panels: identical outer boundary, identical scale, identical position
  - both panels: the SAME quarter view, never mix orthographic and quarter view
  - repeating tileable textures for floors, wall faces, grass and forest
  - fill each panel completely, no margins inside the panels
  - each panel about 3:2 landscape
  - output at least 1800 px on the long side
```

### 프롬프트 진화 기록 (같은 실수를 반복하지 않으려고 남긴다)

| 시도 | 증상 | 넣은 문장 |
|---|---|---|
| 1 | 도식 평면도가 나옴 (게임 맵으로 못 씀) | 화풍 지정 (픽셀아트·쿼터뷰) |
| 2 | 같은 집이 두 벌로 복제됨 | `CRITICAL — count these exactly` + `do NOT duplicate or tile` |
| 3 | `Guest bath` 등 글자 들어감 | `a BLANK UNLABELED map` (단순 `no text` 로는 안 통했다) |
| 4 | 노랑(문 색)이 **그림 판**에 새어 들어감 | `TOP PANEL PALETTE RULE` 블록 분리 |
| 5 | 마스크에 나무를 그림째 복사 | `FLATTEN ... never a drawn tree` |
| 6 | 러그가 가구로 칠해져 거실이 조각남 | `rugs ... ALWAYS #FFFFFF, NEVER #FF00FF` |
| 7 | 판 경계를 못 찾음 (마스크 배경이 검정) | `Separate the two panels with a pure white horizontal band` |
| 8 | 두 판 크기가 4.6% 다름 | `Both panels must be the same width and the same height in pixels` |
| 9 | 문·창문 색이 오판만 늘림 | **범례 8색 → 6색** (문=흰색, 창문=검정으로 흡수) |

**창문·문을 "실제 형태"로 그리는 것은 프롬프트로 못 고친다.** 정투영 톱다운에서
창문은 원래 선이다. 쿼터뷰로 바꾸면 벽면이 보여서 창틀이 그려지지만, 그건 화풍 선택이다.

## 4. 파이프라인 (구현 완료)

```
scripts/map-from-image.mjs --image <파일> --pair v --cell 8 --target 16 --jpeg 85 --connect
```

| 단계 | 모듈 | 하는 일 |
|---|---|---|
| 이미지 읽기 | `src/image-io.mjs` | PNG(자체 디코더) · JPEG(jpeg-js) · 크롭 · 흰 여백 제거 · JPEG 인코딩 |
| 판 분할 | `map-from-image.mjs` | 흰 여백으로 찾고, 없으면 **순수 채도색 밀도**로 찾는다 (그림 판 0~1% vs 마스크 판 13~22%) |
| 마스크 판독 | `src/blueprint.mjs` | 셀 안 픽셀을 하나씩 분류해 투표. 얇은 것(창문·문)은 우선순위로 구제 |
| 타일 추출 | `src/image-tiles.mjs` | 근사 dedup (4×4 블록 평균색을 6단계 양자화) |
| 정렬 검사 | `map-from-image.mjs` | 마스크의 벽이 그림에서도 어두운지 대조. 55% 미만이면 경고 |
| 자동 개통 | `src/auto-connect.mjs` | 끊긴 방을 잇는다. **그림이 밝은 곳(=실제 문)** 을 골라 최소 비용 경로만 뚫고 좌표를 보고 |
| 검증 | `src/spum-map.mjs` | 필수 레이어 · data 길이 · 내비 0/1 · 연결성 · 갇힌 칸 · 스폰 |
| 출력 | `src/map-preview.mjs` · `src/studio-snippet.mjs` | 미리보기 HTML · 칠하기 HTML · 주입 스니펫 |

### 색 체계는 한 곳에

`src/roles.mjs` 가 유일한 정의다. 미리보기·칠하기·범례가 모두 여기서 색을 가져간다.

> **흐린 색 = 지나갈 수 있음 · 진한 색 = 막힘.** 색조가 이유를 말한다.

| 색 | 역할 | 통행 |
|---|---|---|
| 연한 초록 | 실내 바닥 | ✅ |
| 연한 청록 | 야외 지면 | ✅ |
| 연한 노랑 | 문 (열림) | ✅ |
| 빨강 | 벽 | ❌ |
| 주황 | 가구 | ❌ |
| 진한 초록 | 식재 | ❌ |
| 파랑 | 물 | ❌ |
| 청록 | 창문 | ❌ |

화면마다 색이 달라 "빨강이 막힘인가?"를 되묻게 만든 일이 있었다. 그래서 모았다.

## 5. 실측으로 정한 값들 (건드릴 때 근거 확인)

| 값 | 위치 | 왜 이 값인가 |
|---|---|---|
| 근사 dedup (blocks 4, levels 6) | `image-tiles.mjs` | **완전 일치로는 256칸이 256장** 그대로였다 (반복률 0%). 근사로 59장 |
| `satCut = 0.55` | `blueprint.mjs` | 0.22 일 때 나무 줄기 갈색(h47 s0.32)이 노랑으로 가 **문 787칸** 오판. 0.55 로 272칸 |
| 색조 기반 매칭 | `blueprint.mjs` | RGB 유클리드는 어두운 마젠타(128,0,128)를 회색으로, 어두운 초록(0,96,0)을 검정으로 오판 |
| `wall 우선 0.5` | `blueprint.mjs` | 0.18 일 때 마스크 윤곽선만 있으면 뭐든 벽으로 이겨 **야자수까지 벽**(474칸). 0.5 로 243칸 |
| 시트 JPEG | `map-from-image.mjs` | 타일 927장이면 PNG 1,805KB → JPEG 품질 88 로 **301KB**. SPUM 은 `imageUrl` 을 `<img>` 로 로드해 형식을 안 가린다 |
| `--cell 8 --target 16` | CLI | 셀 8px 이면 벽 두께(8px)와 1:1 로 맞는다. 타일 16px 이 용량상 유리 (308KB vs 838KB) |
| 스폰 = 최대 연결 영역 | `map-from-image.mjs` | 첫 통행 칸을 쓰면 구석 한 칸이 잡혀 도달률 15% 로 나왔다 |
| `--connect-max 5` | `auto-connect.mjs` | 두꺼운 벽을 관통해 엉뚱한 구멍을 내지 않게 |

### villa7 최종 성적

```
896×592 두 판 (크기 완전 일치) · 112×74 = 8,288칸 · 고유 타일 6,364장 · 시트 507KB

자동 개통 8칸 → 영역 50개 → 45개
통행 3,861칸 · 도달 3,744칸 (55% → 97%)
```

## 6. 스킬 설계안

### 이름과 진입

`/spum-map` — 이미지를 주면 맵을, 주제를 주면 프롬프트를 낸다.

| 사용자 입력 | 스킬 동작 |
|---|---|
| *"중세 성 내부 맵 만들어줘"* | 프롬프트 생성 → 저장 위치 안내 → 대기 |
| *"생성했어"* / 파일 경로 | 다운로드 폴더 최신 이미지를 찾아 파이프라인 실행 |
| *"이 이미지로 맵 만들어줘"* + 경로 | 같음 |
| *"칠했어"* + JSON | `--cells` 로 재생성 |

### 스킬이 판단할 것

1. **모드 선택** — 짝 이미지(`--pair`) / 타일맵 이미지 / 도면 판독(`--plan`) / 레이아웃 DSL
   - 순수 채도색이 5% 이상이면 짝 이미지로 본다
2. **격자 크기** — 이미지 크기에서 셀 8px 기준으로 잡고, 벽 두께를 재서 조정
3. **자동 개통 여부** — 도달률 90% 미만이면 `--connect` 를 켜고 결과를 보고
4. **재생성 권유 기준** — 정렬 55% 미만 · 두 판 종횡비 6% 초과 · 그림 판에 순수색 검출

### 스킬이 반드시 보고할 것

- 판 분할 경계와 두 판 크기 (종횡비 차)
- 마스크 판독 분포 (역할별 칸수)
- 정렬 일치도
- 고유 타일 수 · 시트 크기
- 통행 칸수 · 도달률 · 영역 개수
- **자동 개통으로 뚫은 좌표 전부** (조용히 벽에 구멍 내지 않는다)
- 미리보기 URL · 칠하기 URL · 스니펫 경로

### 안전 규칙 (스킬 문서에 박아둔다)

- 스니펫은 `sv_studio_maps_v1` 만 건드린다. **전체 교체 파일을 만들지 않는다**
- 작업 전 Studio 백업을 권한다
- 타일이 안 보이면 `MAP STRUCTURE > Layers` 의 NAV 체크박스
- 콘솔 붙여넣기가 막히면 `allow pasting` → `Sources → Snippets`

## 7. 내일 검토할 것

1. **스니펫 크기** — villa7 은 시트 507KB, 스니펫 700KB 대. 콘솔 붙여넣기에 부담.
   품질을 낮출지(85→70), 격자를 굵게 할지, 다른 주입 경로를 쓸지
2. **타일 16px vs 32px** — SPUM 기본은 32px. 16px 이면 캐릭터가 타일 2~4칸을 차지.
   이미지를 1800px+ 로 받으면 확대 없이 32px 을 쓸 수 있다
3. **Studio 왕복 미검증** — 이 파이프라인으로 만든 맵을 아직 Studio 에 넣어보지 않았다.
   프로토 타일셋으로는 전 필드 일치를 확인했으나 **JPEG 시트·6천 타일 규모는 미검증**
4. **가구 통행 정책** — 지금 가구는 전부 막힘. 낮은 러그·카펫만 통행으로 뺐다.
   테이블 아래를 지나갈지 등은 게임 설계 문제
5. **자동 개통 오작동 여지** — 밝기 단서가 없는 화풍에서는 엉뚱한 곳을 뚫을 수 있다.
   뚫은 자리를 미리보기에서 눈으로 확인하는 절차를 스킬에 넣을지
6. **도면 판독 모드(`--plan`)의 쓸모** — 짝 이미지가 훨씬 정확해서 우선순위가 낮아졌다.
   유지할지 정리할지

### 의존성

`jpeg-js` 하나. 이미지 디코딩은 표준 라이브러리 밖이라 여기서만 예외를 뒀다.
없으면 PNG 만 읽고 JPEG 는 안내 메시지를 낸다.

### 시험 자료

`out/masks/` 에 이번에 쓴 이미지들이 남아 있다 (`villa7.jpeg` 가 최종).
`out/masks/_selftest.png` 는 제가 그린 색 마스크로, 판독기 자체 검증용이다 (저신뢰 0칸).
